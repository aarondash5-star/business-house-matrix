# Dev Matrix — Gate S: intelligent supervisor before Gate E

**Date:** 2026-10-23. **Status:** nonproduction, separate staged candidate; **NOT certified or deployed as the live supervisor**.

## Owner decision and rationale
Owner explicitly selected **supervisor-first**: document the current Business House Matrix Dev stack, implement and test an intelligent decision/delegation layer, then return to multi-file coding Gate E only after Supervisor Gate S acceptance. Existing Gate E Python proposers (Granite 3B and Qwen4B variants) did not pass independent QA. The protected v6 controller is a durable allowlisted dispatcher, not an intelligent task-planning model. The `matrix/graph.py` LangGraph sample labels itself a simulation.

## Plain-language structure
- **Owner:** defines the business task and approvals.
- **Supervisor candidate (new Gate S):** proposes ordered tasks, worker roles, dependencies, quality requirements, corrective actions. Never directly executes.
- **Certified v6 Controller (unchanged):** existing trusted dispatcher and permissions boundary. Remains sole existing controller; Gate S does not integrate or switch traffic.
- **Worker roles:** research, design, coding, QA, security and human review. Model chooses a role from an exact allowlist; trusted code maps roles to fixed, non-executing work order names.
- **Dell/Mac:** Dell is staging/QA worker; Mac is an additional independent cross-host reviewer when online.
- **Independent QA + Gate E:** validates real worker output and requires approval before canary, push/merge or production.

## Technical design, source, scope
New isolated branch `feat/dev-supervisor-gate-s-20261023` based on `main`, intentionally separate from draft Gate E PR #13 and certified v6 source.
- `brain/supervisor/gate_s.py`: strict structured JSON `summary,steps`; 4–6 steps, sequential IDs, only six roles, ordered dependencies, QA → security → human review, no model-supplied tools/commands or execution. `route_preview()` outputs role-to-trusted-worker preview only (`execute=false`, `push=false`, `publish=false`). `assess_receipt()` independently handles QA failures, security denial, timeout and missing evidence with fail-closed, single-replan recommendation **without replaying any job**.
- `tests/test_gate_s_supervisor.py`: 20 deterministic unit/negative tests including unknown role/tool/schema denial, dependency bypass, QA/security omission, prompt-injection data not executed, timeout/retry and missing verification gates.
- The only live model adapter in this first prototype is a hardcoded **local Ollama `qwen3:4b-instruct`** plan-only smoke, constrained to one fixed public non-sensitive example and structured JSON. This is a transport/cognitive smoke, **not** a claim that Qwen4B is a sufficiently capable supervisor. The recommended stronger controller model(s) must be separately enrolled using existing approved authenticated inference paths. No credential reading, provider connection change or spending.
- Supervisor model response is never treated as an action permission. No real MCP tool dispatch, no root/SSH change, no remote commands generated by models, no publishing/spending. Any future tool/router integration requires approved allowlist, explicit owner authorization, cross-host and external security QA.

## Gates and acceptance criteria (separate evidence for each)
1. **S0 code/security contract:** isolated staging, deterministic unit and negative tests, trusted worker mapping, all policy escapes blocked (100%), existing certified v6 checksum intact.
2. **S1 real model planning:** real model output, not a stub; benchmark at least 20 diverse public Dev requests, including ambiguous requirements and unavailable workers. Record per-run model ID, model response, accepted/rejected plan, latency/token budget. Target >=90% strict-plan acceptance for appropriate requests; all unauthorized requests fail closed.
3. **S2 delegation/recovery:** no autonomous execution, simulate failing coding/QA/SSH, security denial, retries; 100% deny bypass and no blind replay; >=90% appropriate diagnostic outcomes on holdout cases.
4. **S3 strong model comparison:** compare at least two open-weight, correctly licensed supervisor models, including a stronger remotely served contender if securely available, with equal constraints and total cost/latency. A local 4B smoke cannot justify controller selection.
5. **S4 independent certification:** GitHub CI on exact source, independent Dell/Mac review and error injection, production parity, owner signoff. Only after those gates, consider separate staged adapter to the existing v6 controller with human approval, observability and rollback; no automatic cutover.
